# Go Chat Local

Локальный AI-чат на Go + llama.cpp с веб-интерфейсом и базами знаний в Markdown.
Никаких внешних API — всё работает на твоём компьютере.

Разработано командой https://geriot.ru/

## Возможности

- 🌐 **Веб-интерфейс** — открывается в браузере, ответы рендерятся как Markdown (код, списки, таблицы, цитаты)
- 🗂 **Базы знаний** — `.md` файлы из папки `bases/`, редактируются прямо в UI
- ⚡ **Параллельный анализ** — каждая база отвечает на вопрос одновременно, в чате видно какой раздел выбран и что предложили остальные
- ⚙️ **Настройки из UI** — контекст, потоки CPU, температура, top-p, max tokens
- 💻 **Терминальный режим** — если браузер не нужен (`-cli`)
- 🔒 **Полностью офлайн** — ни один запрос не уходит в сеть

## Требования

| Компонент | Что нужно |
|---|---|
| Go | 1.22+ |
| llama-server | из [релизов llama.cpp](https://github.com/ggml-org/llama.cpp/releases/latest), архив `bin-win-cpu-x64` / `bin-linux-x64-cpu` |
| Модель `.gguf` | от 800 МБ (1B) до 8 ГБ (7B) |
| RAM | 2 ГБ на 1B модель, 4 ГБ на 3B, 8 ГБ на 7B |

## Установка

```bash
git clone https://github.com/<твой-аккаунт>/go-chat-local.git
cd go-chat-local

# 1. Распакуй llama-server в ./bin/
#    (для Linux/macOS не забудь chmod +x)

# 2. Скачай модель и положи как ./models/model.gguf

# 3. Собери
go build -o go-chat-local
```

Примеры моделей:

| Модель | Размер | RAM |
|---|---|---|
| Llama 3.2 1B Instruct Q4_K_M | 800 МБ | 2 ГБ |
| Llama 3.2 3B Instruct Q4_K_M | 2 ГБ | 4 ГБ |
| Qwen2.5 3B Instruct Q4_K_M | 2 ГБ | 4 ГБ |

## Запуск

```bash
./go-chat-local                 # веб-интерфейс на http://127.0.0.1:8765 (откроется браузер)
./go-chat-local -port 9000      # другой порт
./go-chat-local -no-open        # не открывать браузер автоматически
./go-chat-local -host 0.0.0.0   # доступ из локальной сети
./go-chat-local -cli            # терминальный чат
./go-chat-local -h              # справка
```

При первом запуске чат сам поднимает `llama-server`, ждёт готовности модели
и открывает UI в браузере.

## Базы знаний

Каждая база — обычный Markdown-файл с YAML-фронтматтером:

```markdown
---
name: Go
description: Язык Go: горутины, каналы, модули, интерфейсы, тестирование
---

# Go (Golang)

## Горутины и каналы
...
```

- `name` — имя темы для классификатора (если не задать, возьмётся имя файла)
- `description` — ключевые слова, по которым модель выбирает базу
- всё остальное — содержимое базы, попадающее в контекст

Файлы можно создавать, редактировать и удалять прямо в UI (вкладка «Базы»),
либо просто положи `.md` в папку `bases/` и нажми «Перечитать базы».

### Как выбирается база

1. **Параллельный анализ** — каждая база получает вопрос и отвечает параллельно:
   либо даёт короткий ответ, либо возвращает `N/A: <почему не по теме>`
2. **Классификатор** — модель выбирает одну тему из списка
3. **Сводка** — нерелевантные ответы отбрасываются, релевантные попадают в финальный
   system-промпт как подсказки
4. **Ответ** — модель отвечает, опираясь на выбранную базу; если другая база
   релевантнее, LLM сама порекомендует переключиться

В чате это видно как панель «Параллельный анализ по N базам» с отметкой ✓
у выбранной базы.

## Настройки

Меняются в UI (вкладка «Настройки») и сохраняются в `settings.json`:

```json
{
  "context_size": 4096,
  "threads": 8,
  "max_tokens": 512,
  "temperature": 0.7,
  "top_p": 0.9
}
```

> `context_size` и `threads` применяются только после перезапуска llama-server
> (кнопка «Перезапустить сервер»).

### Переменные окружения

| Переменная | Что | По умолчанию |
|---|---|---|
| `LLAMA_BINARY` | путь к llama-server | `./bin/llama-server` |
| `LLAMA_MODEL` | путь к `.gguf` | `./models/model.gguf` |
| `LLAMA_HOST` | хост сервера | `127.0.0.1` |
| `LLAMA_PORT` | порт llama-server | `8080` |
| `LLAMA_NO_AUTOSTART` | `1` — не запускать сервер самому | `0` |

## HTTP API

UI работает поверх локального сервера, его же можно использовать из своих скриптов.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/state` | конфиг, статус сервера, список баз |
| `POST` | `/api/config` | изменить настройки генерации |
| `POST` | `/api/chat` | `{message}` → `{response, source, analyses[]}` |
| `POST` | `/api/clear` | очистить историю |
| `POST` | `/api/restart` | перезапустить llama-server |
| `POST` | `/api/reload` | перечитать папку `bases/` |
| `GET` | `/api/bases` | список баз |
| `GET` | `/api/bases/{name}` | содержимое базы |
| `PUT` | `/api/bases/{name}` | сохранить базу |
| `POST` | `/api/bases` | создать базу |
| `DELETE` | `/api/bases/{name}` | удалить базу |

Пример:

```bash
curl -X POST localhost:8765/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"Как создать горутину в Go?"}'
```

Ответ:

```json
{
  "response": "Горутина создаётся ключевым словом go...",
  "source": "Go",
  "analyses": [
    {"name": "Bash", "answer": "N/A: вопрос не про командную строку", "chosen": false},
    {"name": "Go",   "answer": "Горутины запускаются через go func(){}", "chosen": true},
    {"name": "Python","answer": "N/A: в Python это asyncio", "chosen": false}
  ]
}
```

## Зависимости

Только стандартная библиотека Go — включая HTTP-сервер и встраивание статики
через `embed`. Сторонних пакетов в `go.mod` нет, markdown рендерится
собственным скриптом на ~80 строк.

## Безопасность

Сервер слушает только на `127.0.0.1` по умолчанию и не имеет аутентификации.
Если поднимаешь наружу (`-host 0.0.0.0`), имей в виду: любой, кто видит порт,
получит доступ к модели и к API редактирования баз. Не выставляй в интернет.

## Решение проблем

**«не найден llama-server»** — положи бинарь в `./bin/`, на Linux/macOS `chmod +x ./bin/llama-server`

**«не найдена модель»** — файл должен называться `model.gguf` и лежать в `./models/`

**«сервер не ответил за 60 сек»** — смотри `llama-server.log`. Обычно модель не помещается в RAM или порт занят

**«порт уже занят»** — укажи другой: `./go-chat-local -port 9000`

**Долгий ответ при большом числе баз** — параллельный анализ умножает число запросов на количество баз. Удали неиспользуемые базы или оставь 2–4 релевантных
